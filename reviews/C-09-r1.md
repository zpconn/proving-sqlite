## Checklist
1. **SQLite's code.** The harness includes the overlay and calls sqlite3VdbeSerialGet directly. serialGet runs its
   real body: no REPLACE, no ENFORCE. The overlay has 0 spans and the diff touches only the card's three files plus the report.
   The SETUP `extent` ternary is the spec table's sizes, not SQLite code. Assertion 1 checks it against the frozen
   `ref_serial_bytes`, and it is proved.
2. **Bytes unconstrained.** The input is `malloc(extent)`, so its contents are nondet. The only assume is
   `bytes != 0 || extent == 0`, which constrains no data byte. The allocation is exactly k bytes, the tightest P3
   allows. `decoded` is an uninitialized local, so every Mem field starts nondet. serial_type is any u32.
3. **Requires necessary.** I deleted the one assume in a scratch copy (/tmp/rv/noassume): it fails with FAILURE
   `serialGet.pointer_arithmetic.1 line 91950 pointer NULL in buf + 0`. Footprint minus one, lp64-le, one run per t
   (/tmp/rv/shortT). Each FAILURE is in SQLite itself:
   t=1 `sqlite3VdbeSerialGet.pointer_dereference.35` 92019 buf[0];
   t=2 `.59` 92027;
   t=3 `.89` 92035;
   t=4 `.125` 92043;
   t=5 `.161` 92055 (buf+2)[3];
   t=6 and t=7 `serialGet.pointer_dereference.47` 91951 (buf+4)[3].
   This matches the report's table. The card has no in-scope callers, and P3's own premise supplies the readable bytes,
   so no ledger draft is needed.
4. **Not vacuous.** A scratch harness with `__CPROVER_assert(0,"reach")` after the call fails (1 failed), so the
   post-call checks are reachable. Coverage is 40/40 and 10/10 lines per configuration, so every case's `return` is
   reached. All 7 mutants are killed.
5. **Ensures/assigns.** This is a relational P3 harness and has no contract. `ref_serial_get` (frozen) checks
   exactly the fields PROPERTIES.md P3 names. Neither decoder writes the input, so the reference sees the
   bytes the decoder read.
6. **Loops.** SQLite has none here. The only loop is `ref_be.0` (≤8 iterations), unwound with `ref_be.0:9` and
   unwinding assertions on.
7. **Boundary contracts.** None used.
8. **Findings.** None claimed. The short and NULL variants violate P3's premise, and the report rightly says they
   are not findings.
9. **Words.** "Proved" claims match what CBMC verified on all three configurations. See minor issue 1.
