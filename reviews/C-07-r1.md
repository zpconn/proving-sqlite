## Issues
1. **minor** — `w_ok(pMem, sizeof(Mem))` is larger than the code needs.
   - Evidence: with `w_ok(pMem, sizeof(Mem)-1)` in both contracts (/tmp/r/wok1): `RESULT prove C-07 lp64-le PASS 65s 437 properties 0 failed`. GOAL checklist 3 says a footprint's value minus one must fail; this one does not, because only `u` and `flags` (the first ~10 bytes) are written. The report/NOTES say sizeof(Mem) "expresses a valid output object", which is honest, but the "required value minus one" test was not done for this clause.
   - Impact: none for soundness. Both in-scope callers pass a whole Mem (C-17's automatic `mem1`; C-08's pMem), so the stronger requires is met at every site.
   - Fix (optional, a later round or C-08 can live with it): state the footprint as `__CPROVER_w_ok(pMem, offsetof(Mem, flags) + sizeof(pMem->flags))` or keep sizeof(Mem) and say in NOTES that it is the whole-object convention, deliberately not minimal. Orchestrator to file; C-08 and C-17 must carry `w_ok(pMem, sizeof(Mem))` (or the weaker form) into their own contracts.
2. **minor (carry-over for C-08/C-17)** — the 8-readable-bytes requires is not established by any code at the C-17 call sites; it depends on A-001's slack. C-17 must give its S and show it covers `d1 + 8`. C-08 must require `r_ok(buf, 8)` (or equivalent) for serial types 6 and 7 only if its own proof shows it; types 1..5 read fewer bytes.
