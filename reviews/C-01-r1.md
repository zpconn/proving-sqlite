## Issues

1. **MAJOR: neither requires is necessary to the proof (checklist 3).**
   - harness.c passes `unsigned char output[9]` (a fixed 9-byte local, offset 0) to both functions. That object always satisfies `__CPROVER_w_ok(p,9)`, so the requires never restricts any state.
   - I deleted each requires in a scratch copy (lp64-le):
     - putVarint64.h without its requires: `RESULT prove C-01 lp64-le PASS ... 182 properties 0 failed`.
     - sqlite3PutVarint.h without its requires: `PASS ... 187 properties 0 failed`.
   - The checklist says the proof must fail without a requires. It doesn't.
   - The proof therefore covers only one pointer (base of an exactly-9-byte object). The contract it claims is for every `p` with `w_ok(p,9)`.
   - This conflicts with builder GOAL §2.3 (start unconstrained, add a requires only when a counterexample shows it's needed). The NOTES.md table's "counterexample without sufficient extent" row comes from a different experiment (8-byte objects), not from removing the requires.
   - The 9-byte extent is shown necessary only through the footprint-minus-one test. That part is sound.
   - Fix: let the harness choose the allocation size in a SETUP block, e.g. `size_t n; unsigned char *p; __CPROVER_assume(n<=16); p=malloc(n);` (no data-byte assumes), and let the contract's requires exclude n<9. I tried this in /tmp/r1/sG and /tmp/r1/sH, both lp64-le:
     - sG, requires kept: `RESULT prove C-01 lp64-le PASS ... 197 properties 0 failed`.
     - sH, requires deleted: `RESULT prove C-01 lp64-le FAIL ... 130 failed`.
   - So this harness shape works with the existing toolchain and makes each requires demonstrably necessary. Then redo the delete-requires check for both contracts and record the failing result in NOTES.md.
   - A plain uninitialized `unsigned char *p` does not work: sE failed even with the requires kept.
