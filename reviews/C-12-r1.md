## Checklist
1. **SQLite's code.** The overlay diff is one PROOF span on the loop at 92371, between the `)` and the body, with assigns/invariant/decreases in the required order. No other overlay change. The harness calls `isAllZero` itself.
2. **Bytes unconstrained.** SETUP holds only `extent <= INT_MAX && offset <= extent`, `malloc(extent)` and `input != 0`. `length` is an unrestricted int and the bytes are never touched. The allocation is nondet in size, so short, exact, longer, interior and one-past tails are all covered, and nothing is sized to fit only good inputs. The one SETUP assume is in the allowed block.
3. **Requires.** The sole requires is `n <= 0 || __CPROVER_r_ok(z,n)`. It is necessary and exact, per the two scratch runs above.
   Caller at upstream 92750-92760 (`sqlite3VdbeRecordCompareWithSkip`): `serial_type` is u32 and passes the `>=12 && even` test, so `nStr=(serial_type-12)/2` is in [0, 2^31-7] and fits an int. The call passes `&aKey1[d1], nStr` after `d1+nStr <= (unsigned)nKey1`. That supplies the n-byte extent, provided C-17 discharges it at the call site (C-17 must also look at the u32 wrap of `d1+nStr`, which is its card's matter and not C-12's). The card names no ledger entries and none is needed.
4. **Not vacuous.** The return is reachable: the lines holding both returns and the byte read are covered. The only gap is 92371. In `zero.cover.cbmc` the failed blocks are `isAllZero_wrapped_for_contract_checking` blocks 6-15 (dead preheader copy), 28 and 52 (base/non-base branches of the DFCC `__in_base_case` flag), all mapped to the loop-header line. Both mutants are killed and are not equivalent.
5. **Ensures/assigns.** Ensures is `return in {0,1}`. Assigns is empty, which is right because the function writes only its local `i`. C-17 needs only the Boolean result for P1, so this is sufficient. No functional ensures is claimed, and none is needed for P1.
6. **Loop.** assigns `i`, invariant `0<=i<=max(n,0)`, decreases `n>0 ? n-i : 0`. The invariant constrains only the index and not the data. Proved on all three configs: no overflow, and the unwinding assertions pass.
7. **Boundary contracts.** None used.
8. **Findings.** None (no repro).
9. **Words.** Proved, Tested, Assumed and Trusted are used correctly. The report states that the CBMC malloc model returns NULL for very large objects, and the claim is limited accordingly.
